## GEO-INFER-EMERGENCY — Emergency Management and Disaster Response

GEO-INFER-EMERGENCY provides emergency management and disaster response capabilities for geospatial systems (module README). It sits in the Spatial & Place-based theme, applying the framework's spatial machinery to time-critical scenarios — evacuation, resource deployment, and search-and-rescue — where geographic accuracy directly affects outcomes.

Despite a compact codebase of eight source files, the module exposes five coordinated public classes from `src/geo_infer_emergency/__init__.py`: `EmergencyCoordinator` as the central orchestrator, `ResourceDeployer` for positioning response assets, `EvacuationPlanner` for routing populations away from hazard zones, `SituationalAwareness` for maintaining a live operational picture, and `SearchAndRescue` for locating and recovering affected people. The narrow API is deliberate: emergency workflows value a small, well-tested command surface over broad configurability, and the module's `pyproject.toml` dependencies are correspondingly focused.

The test suite is the module's proof of reliability, and its structure reflects the stakes. `tests/` holds eight test modules (plus `conftest.py`) — coordinator, evacuation, resource, awareness, SAR-focused files (`test_sar.py`, `test_evacuation_sar.py`), geography checks (`test_geo.py`), and an acceptance suite (`test_acceptance_emergency.py`) — with 164 test functions in total. An explicit acceptance file is notable: it encodes end-to-end response scenarios, not just unit behavior. For a module where failure is measured in lives, EMERGENCY demonstrates the framework's pattern of small APIs backed by dense, scenario-level verification.
