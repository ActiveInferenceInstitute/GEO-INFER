## GEO-INFER-GIT — Geospatial Repository Cloning and Management

GEO-INFER-GIT provides version control and repository management tools specifically designed for geospatial data and code collaboration (module README). In practice it is the framework's repository-integration utility: cloning GitHub repositories by user and configuration, analyzing their structure, and coordinating distributed work. It belongs to the Infrastructure & Validation theme alongside INTRA, TEST, LOG, and EXAMPLES.

The `geo_infer_git` package (per `src/geo_infer_git/__init__.py`, version 0.3.0) is organized into `core`, `api`, `config`, and `utils` subpackages with a `cli.py` and `main.py` entry points. The core layer carries the working machinery: `RepoCloner` with `CloneProgress` for batch cloning, `RepoManager` for repository lifecycle, `RepoAnalyzer` for structural analysis, plus `GitHubAPI` with `GitHubRepository` and `RateLimit` types, and `advanced_git.py` and `multi_platform_api.py` for extended operations and non-GitHub hosts. The API layer wraps this in a REST service: `rest_api.py` defines Pydantic request/response models (`RepositoryRequest`, `CloneRequest`, `SyncRequest`, `BranchRequest` and their responses) behind an `ErrorHandlerMiddleware`, so cloning and syncing are callable over HTTP as well as CLI.

Evidence is the densest in the E-L band: `tests/unit/` holds 18 files with 241 test functions, plus one integration file, 242 tests total. For a module that manipulates external state (remote repositories, rate limits), that unit-test depth is the primary guard against integration breakage.
