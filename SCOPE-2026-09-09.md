### SC-1 — Wire the stale-artifact gate into CI

- **Severity**: major
- **Category**: tests / DX
- **Motivation**: `check_published_artifacts()` (manuscript/generate_research_artifacts.py:2027-2080, CLI `--check` at :2083-2147) is the only gate that detects a committed-but-stale published bundle, and **no workflow runs it**. CI's manuscript job runs `--verify` (regenerates), so a commit that changes source without republishing exits green. Demonstrated live: `uv run python manuscript/generate_research_artifacts.py --check` → exit 1, `RESEARCH_SOURCE_HASH is stale: published '4f76540c4edb0328', measured '0ad98a3dc8592ee7'` on this branch, while the `--verify` CI path passes.
- **Scope**: `.github/workflows/ci.yml` manuscript job — add a step running `uv run python manuscript/generate_research_artifacts.py --check` (after regeneration, before artifact upload), with the failure surfaced in the job summary.
- **Acceptance probe**: `uv run python manuscript/generate_research_artifacts.py --check` exits 0 after regen; `git grep -n '\-\-check' .github/workflows/ci.yml` shows the step.
- **Effort**: S
- **Order**: first quick win; blocks SC-20's meaning (regen without the gate re-drifts silently).
